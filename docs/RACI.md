# RACI inicial

Leyenda: R = Responsible (ejecuta), A = Accountable (decide/responde), C = Consulted, I = Informed. Equipo técnico propuesto a validar; PO/SM fijados.

| Actividad | Vanessa (PO) | Javi (SM) | Juan Manuel | Isabela | Luis |
|---|---:|---:|---:|---:|---:|
| Vision, alcance, prioridad, aceptación | A/R | C | C | C | C |
| Sprint, bloqueos, retro, flujo de trabajo | C | A/R | R | R | R |
| Auditoría legacy y pipeline de datos | A | C | R | C | C |
| Fuentes/licencias de datos | A | C | R | I | C |
| API, permisos y esquema SQL | C | C | C | C | A/R |
| UI y journeys candidate/company | A | C | C | R | C |
| Matching/embedding/evaluación | A | C | R | C | R |
| Privacidad, sesgo y AI governance | A | C | R | R | R |
| CI, pruebas e integración | C | A (flujo) | R | R | R |
| Demo/narrativa final | A | R | R | R | R |

No usar RACI para crear silos: se debe acordar un dueño por issue y una revisión cruzada. El reparto técnico es una hipótesis inicial, no una afirmación de experiencia previa.
